# Règles de rédaction de tickets GitHub

## Format
- Toujours se baser sur un template existant

## Règles de style
- Toujours en français
- Ajouter les labels appropriés parmi la liste dispo dans github. Dans le doute, demande à l'utilisateur
- Etre concis (30 lignes maximum)
- Ne pas hésiter à utiliser markdown pour faire des ticket clair et lisibles (sous-titre avec émojis, liste, tableaux, etc...) si nécessaire

## Ce qu'il ne faut PAS faire
- Ne pas assigner de personne sauf si demandé
- Ne pas fermer/modifier/créer des tickets existants sans confirmation

## Ce qu'il ne faut pas oublier
- Ajouter l'issue sur le project Cityborn avec le Type "DEV" et Status "A faire dans l'itération"

**Toujours faire relire une issue avant sa publication sur github**
